# Multi-Resolution Climate Data Pipeline — Requirements

## Overview

Implement a multi-resolution scientific data pipeline using ADIOS2's BP5 engine.
The pipeline ingests 3D simulation fields at full resolution and produces a single
BP5 dataset containing the fields at three resolution levels: full, half (2x
downsampled), and quarter (4x downsampled). An analyzer then reads the dataset,
computes cross-resolution quality metrics, implements adaptive resolution
selection, and outputs a structured JSON report.

## Grid and Time Parameters

- Full resolution shape: (Nx=64, Ny=48, Nz=32)
- Half resolution shape: (32, 24, 16) — 2x downsampling in each dimension
- Quarter resolution shape: (16, 12, 8) — 4x downsampling in each dimension
- Number of timesteps: 8 (step indices 0 through 7)
- Time increment: dt = 0.1
- Physical time at step s: t = s * dt

## Field Computation

Use the provided `/app/fields.py` module. It exports:
- `compute_fields(nx, ny, nz, step, dt)` → dict of 5 float64 arrays
- `VARIABLE_NAMES` = ["velocity_x", "velocity_y", "velocity_z", "temperature", "pressure"]
- `FULL_SHAPE` = (64, 48, 32)
- `NUM_STEPS` = 8
- `DT` = 0.1

Full resolution data is generated by calling `compute_fields(*FULL_SHAPE, step, DT)`.

## BP5 Dataset: `/app/climate.bp`

### Variable Naming Convention

All field variables use the naming pattern `{level}/{variable_name}` where:
- `level` is one of: `full`, `half`, `quarter`
- `variable_name` is one of: `velocity_x`, `velocity_y`, `velocity_z`, `temperature`, `pressure`

Examples: `full/velocity_x`, `half/temperature`, `quarter/pressure`

Additionally, a scalar `physical_time` (float64) is stored at each step without
a level prefix.

### Array Shapes and Write Parameters

Each variable must be written with explicit shape, start, and count parameters:
- `full/*` variables: shape=[64, 48, 32], start=[0, 0, 0], count=[64, 48, 32]
- `half/*` variables: shape=[32, 24, 16], start=[0, 0, 0], count=[32, 24, 16]
- `quarter/*` variables: shape=[16, 12, 8], start=[0, 0, 0], count=[16, 12, 8]

### Downsampling Method: Block-Mean Averaging

Downsampled data must be computed using **block-mean averaging**: partition the
full-resolution 3D array into non-overlapping cubic blocks of size (f, f, f)
where f is the downsample factor, and take the arithmetic mean of each block.

Implementation: reshape array from (Nx, Ny, Nz) to
(Nx/f, f, Ny/f, f, Nz/f, f), then compute .mean(axis=(1, 3, 5)).

- Half (f=2): (64,48,32) → reshape to (32,2, 24,2, 16,2) → mean → (32,24,16)
- Quarter (f=4): (64,48,32) → reshape to (16,4, 12,4, 8,4) → mean → (16,12,8)

### Per-Variable Quality Attributes (written at step 0)

For each downsampled level (`half`, `quarter`) and each variable, compute
quality metrics based on **step 0 data only** and write as attributes:

- `{level}/{variable}/psnr_db` (float64): PSNR in decibels
- `{level}/{variable}/max_abs_error` (float64): maximum absolute reconstruction error

#### PSNR Computation (step 0)

1. Compute full-resolution field `F` of shape (Nx, Ny, Nz)
2. Compute block-mean downsampled field `D`
3. Upsample `D` back to (Nx, Ny, Nz) via nearest-neighbor repetition: `R`
4. `MSE = mean((F - R)^2)`
5. `data_range = max(F) - min(F)`
6. If `MSE == 0`: `psnr_db = 999.0` (sentinel for perfect reconstruction)
7. Otherwise: `psnr_db = 10 * log10(data_range^2 / MSE)`

#### Nearest-Neighbor Upsampling

Repeat each element `f` times along each dimension. For a 3D array, apply
`np.repeat` with factor `f` along axes 0, 1, and 2 sequentially.

#### Max Absolute Error (step 0)

`max_abs_error = max(|F - R|)` where `R` is the nearest-neighbor upsampled
version of the block-mean downsampled data.

### Quality Metrics (across ALL 8 steps)

For each downsampled level and each variable, aggregate over **all** timesteps:

1. For each step s in [0, 7]:
   - Compute full resolution field `F_s` using `compute_fields(*FULL_SHAPE, s, DT)`
   - Compute block-mean downsampled `D_s`
   - Upsample `D_s` to full resolution: `R_s`
   - `MSE_s = mean((F_s - R_s)^2)`
   - `max_err_s = max(|F_s - R_s|)`
2. `MSE_total = mean([MSE_0, MSE_1, ..., MSE_7])`  (mean of per-step MSEs)
3. `max_abs_error = max([max_err_0, ..., max_err_7])`
4. `data_range = max over all steps of (max(F_s) - min(F_s))`
5. If `MSE_total == 0`: `psnr_db = 999.0`
6. Otherwise: `psnr_db = 10 * log10(data_range^2 / MSE_total)`
7. If `data_range == 0`: `nrmse = 0.0`
8. Otherwise: `nrmse = sqrt(MSE_total) / data_range`

Round `psnr_db` to 2 decimal places.
Round `max_abs_error` and `nrmse` to 8 decimal places.

### Adaptive Resolution Selection

For each variable, given NRMSE tolerance thresholds `[0.1, 0.01, 0.001]`,
select the **coarsest** resolution level whose NRMSE is strictly below
the threshold:

- Check from coarsest to finest: `quarter` → `half` → `full`
- If `quarter`'s NRMSE < threshold, select `"quarter"`
- Else if `half`'s NRMSE < threshold, select `"half"`
- Else select `"full"`

The `full` level always has NRMSE = 0, so it always satisfies any threshold.

## Pipeline Execution

Create `/app/run_pipeline.sh` (executable) that:
1. Removes any previous `/app/climate.bp` and `/app/report.json`
2. Runs the writer to produce `/app/climate.bp`
3. Runs the analyzer to produce `/app/report.json`
