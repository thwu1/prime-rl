An iperf3 v3.16 deployment at `/app/` was left partially configured. It has OpenSSL auth support compiled in but no authentication set up, no analysis tooling, and no CVE exposure assessment. Pre-captured test results (four JSON files covering different test modes) are in `/app/captures/`, security advisories in `/app/advisories/`, and version metadata in `/app/deployment_info.json`.

Produce these artifacts:

- **`/app/auth/`** — Contains an RSA 2048-bit keypair as `private.pem` and `public.pem`, plus an iperf3 authorized-users credential file `credentials.csv`. The CSV format is `username,hash` (one line per user, no header) for users `alice`/`benchmark2024`, `bob`/`netperf#secure`, `charlie`/`thr0ughput!`. Each hash is the hex-encoded SHA-256 digest of the string `{username}password` — literal curly braces included (e.g., for alice the input to SHA-256 is the byte string `{alice}benchmark2024`). The public key must correspond to the private key (matching modulus).

- **`/app/analyze.py`** — Reads all captures from `/app/captures/`, auto-detects each test's type from the iperf3 JSON content, computes the metrics specified in `/app/report_schema.json`, classifies each test per `/app/classification_thresholds.json` (check `optimal` first, then `acceptable`, default `degraded`), and writes `/app/analysis_report.json`. The report is a JSON object keyed by capture filename without its `.json` extension (i.e., keys are `tcp_single`, `udp_test`, `tcp_parallel`, `tcp_bidir`). Each entry contains the required fields for its test type as defined in the report schema, plus a `classification` string. For TCP single-stream: `sender_bps`, `receiver_bps`, `retransmits`, `retransmit_rate_per_mb` (retransmits / total MB transferred), `mean_rtt_ms` (convert from microseconds), `throughput_efficiency` (receiver/sender * 100), `cpu_host_total`, `classification`. For UDP: `sender_bps`, `jitter_ms`, `lost_packets`, `total_packets`, `lost_percent`, `out_of_order`, `cpu_host_total`, `classification`. For TCP parallel: `num_streams`, `aggregate_sender_bps`, `aggregate_receiver_bps`, `per_stream_sender_bps` (array), `total_retransmits`, `jains_fairness_index` (Jain's fairness = (sum(x_i))^2 / (n * sum(x_i^2))), `cpu_host_total`, `classification`. For TCP bidirectional: `upload_sender_bps`, `download_sender_bps`, `asymmetry_ratio` (upload/download), `cpu_host_total`, `classification`.

- **`/app/cve_report.json`** — CVE exposure assessment as a JSON object keyed by CVE ID. Must include entries for `CVE-2023-38403`, `CVE-2024-26306`, `CVE-2024-53580`, and `CVE-2025-54351`. Each entry contains: `applicable` (boolean — whether the deployed version 3.16 is affected based on the advisory's version range), `reason` (string explaining the applicability determination, at least 10 characters), `severity` (string: standard CVSS severity level derived from the advisory's CVSS score — `low` for 0.1-3.9, `medium` for 4.0-6.9, `high` for 7.0-8.9, `critical` for 9.0-10.0).

- **`/app/run_auth_test.sh`** — Executable bash script that runs a complete authenticated iperf3 loopback session as user `alice` for 3 seconds with JSON output, saves the result to `/app/auth_test_result.json`, cleans up all iperf3 server processes, and exits 0 on success. The output JSON must be a valid iperf3 result containing `start` and `end` sections.
