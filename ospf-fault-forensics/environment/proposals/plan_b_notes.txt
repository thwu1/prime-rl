Remediation Plan B - Engineer: Bob Martinez
Date: 2026-06-02
Ticket: INC-8842 (OSPF outage - all cross-site connectivity down)

Investigation Summary:
Analyzed OSPF state dumps and routing tables. Found two clear issues:

1. core_rtr has a distribute-list referencing prefix-list MAINT_FILTER that
   denies 10.3.0.0/24. This is from maintenance ticket NET-4471 back in
   April (dist_rtr3 firmware upgrade). The maintenance window closed weeks
   ago but the filter was never removed. Removed the distribute-list line.
   Left the prefix-list definition in place (harmless without the
   distribute-list and serves as documentation of what was done).

2. dist_rtr1 has 'network 10.10.0.0/24 area 0' which doesn't match its
   eth1 subnet (10.1.0.0/24). Rather than just fixing the typo, I broadened
   the network statement to 10.0.0.0/8 to future-proof it -- this way if
   any new host subnets are added to dist_rtr1 they'll automatically be
   included in OSPF without needing a config change.

3. dist_rtr2 and dist_rtr3 configs look correct. dist_rtr2 has
   passive-interface default set but the network statements cover all
   interfaces, so OSPF should handle adjacency formation through the
   network statement matching. No changes needed.

Testing performed:
- Verified dist_rtr3 OSPF adjacency is intact (was already working)
- Confirmed core_rtr no longer filters 10.3.0.0/24
