The pricing system at `/opt/pricing_task/` computes shopping cart totals by applying discount rules against a product catalog. Product data and discount rules are stored in a normalized SQLite database (`supermarket.db`) across four tables: `products`, `discounts`, `discount_params`, and `discount_products`. The current `calculate_optimal_total` function in `pricing_engine.py` delegates to a greedy algorithm that processes discounts in declaration order, frequently producing suboptimal totals when discounts compete for the same items.

Copy the source files to `/app/` and replace the greedy implementation so that `calculate_optimal_total` returns the **globally minimum possible total price** for any given cart. The engine must also implement `load_catalog_from_db` and `load_discounts_from_db` to reconstruct discount rules from the normalized schema — discount parameters are distributed across `discount_params` (keyed by `param_name`/`param_value` pairs that must be cast to their correct types) and product associations live in `discount_products` with varying `role` values.

The five discount types and their semantics are documented in `pricing_engine.py`'s module docstring. Study the database schema with `sqlite3`. The final total must be `round(total, 2)`. A CLI wrapper at `/app/main.py` exercises the engine for manual testing.
