CBPR+ MT103 TO pacs.008.001.08 TRANSLATION GUIDE
==================================================

OVERVIEW
--------
This guide describes the translation of SWIFT MT103 (Single Customer Credit
Transfer) messages to ISO 20022 pacs.008.001.08 under the CBPR+ programme.
The translated output is a BizMsg envelope containing a Business Application
Header (AppHdr) and a pacs.008 Document.

Translation coverage below focuses on header and core field mappings.
For complete field-level details on sender-receiver information, regulatory
reporting, and advanced remittance handling, refer to sample translations
and ISO 20022 message definitions.


ENVELOPE STRUCTURE
------------------
Root element: BizMsg
  +-- AppHdr  (namespace: urn:iso:std:iso:20022:tech:xsd:head.001.001.03)
  +-- Document
        +-- FIToFICstmrCdtTrf  (namespace: urn:iso:std:iso:20022:tech:xsd:pacs.008.001.08)
              +-- GrpHdr
              +-- CdtTrfTxInf


HEADER MAPPING (Blocks 1-3 -> AppHdr)
--------------------------------------
Block 1 contains the sender Logical Terminal address.
  Format: F01<BIC8><LT_code><branch_code>...
  Extract BIC: characters [3:11] = BIC8, skip LT code at [11], branch at [12:15]
  -> AppHdr/Fr/FIId/FinInstnId/BICFI

Block 2 contains the message type, receiver, and priority indicator.
  Format: I103<BIC8><LT_code><branch_code><priority>
  Extract receiver BIC: characters [4:12], skip [12], branch [13:16]
  Priority at position [16]: U -> HIGH, N -> NORM
  -> AppHdr/To/FIId/FinInstnId/BICFI
  -> AppHdr/Prty

Block 3 sub-fields:
  {108:value}  -> AppHdr/BizMsgIdr
  {119:STP}    -> PmtTpInf/SvcLvl/Cd = "G004"
  {121:uuid}   -> PmtId/UETR

Fixed values:
  AppHdr/MsgDefIdr = "pacs.008.001.08"
  AppHdr/BizSvc = "swift.cbprplus.02"


CORE FIELD MAPPING (Block 4 -> GrpHdr + CdtTrfTxInf)
------------------------------------------------------
:20: Sender's Reference
  -> GrpHdr/MsgId
  -> PmtId/TxId
  -> PmtId/InstrId (default; may be overridden by remittance code words)

:32A: Value Date / Currency / Amount
  Format: YYMMDD CCY Amount (comma decimal)
  -> IntrBkSttlmDt (convert YYMMDD to YYYY-MM-DD)
  -> IntrBkSttlmAmt with Ccy attribute (convert comma to period)

:33B: Currency / Instructed Amount
  -> InstdAmt with Ccy attribute

:36: Exchange Rate
  -> XchgRate (convert comma to period)

:71A: Details of Charges
  BEN -> ChrgBr = CRED
  OUR -> ChrgBr = DEBT
  SHA -> ChrgBr = SHAR


PARTY MAPPING
--------------
:50K: Ordering Customer (unstructured)
  First line starting with / = account number
  Remaining lines = name + address
  -> Dbtr/Nm, Dbtr/PstlAdr/AdrLine, DbtrAcct

:50A: Ordering Customer (BIC)
  Optional /account on first line
  BIC on next line
  -> Dbtr/Id/OrgId/AnyBIC, DbtrAcct

:50F: Ordering Customer (structured)
  Numbered lines with semantic codes:
    1/ = name, 2/ = address, 3/ = country/town
  Account or identity code on first line
  -> Dbtr with structured postal address (Ctry, TwnNm, AdrLine)

:59: Beneficiary Customer (unstructured)
  Same structure as 50K
  -> Cdtr/Nm, Cdtr/PstlAdr/AdrLine, CdtrAcct

:59F: Beneficiary Customer (structured)
  Same structure as 50F
  -> Cdtr with structured postal address

:59A: Beneficiary Customer (BIC)
  -> Cdtr/Id/OrgId/AnyBIC, CdtrAcct


AGENT MAPPING
--------------
:52A/D: Ordering Institution -> DbtrAgt
  If absent, DbtrAgt defaults to the sender BIC.

:57A/D: Account With Institution -> CdtrAgt
  If absent, CdtrAgt defaults to the receiver BIC.
  When /account is present -> CdtrAgtAcct

Agent fields with option A carry a BIC; option D carries name + address.


CORRESPONDENT AND SETTLEMENT AGENTS
-------------------------------------
Fields 53, 54, and 56 define the payment chain intermediaries.
The settlement method (SttlmMtd) is derived from which of these fields
are present. Correspondent agent fields map to reimbursement and
intermediary agent elements under SttlmInf and CdtTrfTxInf respectively.

:56A/D: Intermediary Institution -> IntrmyAgt1
  When /account is present -> IntrmyAgt1Acct


REMITTANCE AND INSTRUCTION FIELDS
-----------------------------------
:70: Remittance Information -> RmtInf
  May contain free text and/or code words that trigger structured
  remittance elements. Certain code words can override payment
  identification fields.

:72: Sender to Receiver Information
  Contains code words that route to different instruction and agent
  elements. Continuation lines (starting with //) append to the
  preceding code word context.

:77B: Regulatory Reporting -> RgltryRptg
  Contains jurisdiction-specific regulatory codes with country and
  detail information.

:71F: Sender's Charges -> ChrgsInf (agent = sender BIC)
:71G: Receiver's Charges -> ChrgsInf (agent = receiver BIC)

:23E: Instruction Code
  Some codes map to InstrForCdtrAgt/Cd, others to category purpose
  or instruction priority.

:26T: Transaction Type Code -> PmtTpInf/LclInstrm/Cd

:13C: Time Indication
  Contains time codes with timestamps that map to settlement
  time indication elements.
