An asyncio TCP server skeleton at `/app/server.py` handles connection lifecycle, binary message parsing, client identity management, and heartbeat scheduling for the Speed Daemon protocol specified in `/app/protocol_spec.md`. The system coordinates average-speed enforcement across a road network: ANPR cameras report plate sightings with mile positions and timestamps, and ticket dispatcher clients receive binary-encoded violation notices.

The skeleton correctly handles protocol framing and all client→server message types, but the enforcement engine is entirely absent — observations are recorded with no violation analysis, and dispatchers register but receive no tickets. The server needs: speed-violation detection across all observation pairs on each road, ticket generation with correct binary serialization, per-car-per-day deduplication with multi-day span coverage tracking, ticket buffering for roads without an active dispatcher, and dispatcher lifecycle cleanup on disconnect.

**Caution**: not all utility functions in the skeleton have been validated against the protocol specification. A reference packet capture from a known-conformant implementation is at `/app/traces/reference.pcap`, with raw protocol messages in `/app/traces/messages/`. Verify the skeleton's binary encoding against trace data before building on it. Network analysis tools are available: `tshark`, `tcpdump`, `socat`, `xxd`, `nc`.

Design and implement the complete enforcement engine in `/app/server.py`. The finished server must be started with `python3 /app/server.py` and listen on TCP port 9000.
