Intel 8086 Microcode-Level Integer Multiplication and Division Specification
==============================================================================

This document describes the internal algorithms used by the Intel 8086 processor
for integer multiplication and division, as reconstructed from die-level reverse
engineering of the microcode ROM.

REGISTER MODEL
--------------
The 8086's ALU has three internal temporary registers invisible to the programmer:
  tmpA  - 16-bit temporary register A
  tmpB  - 16-bit temporary register B
  tmpC  - 16-bit temporary register C

Additional internal state:
  CF    - carry flag (1-bit), updated by ALU operations
  F1    - internal flag (1-bit), used to track sign during signed mul/div
  CNT   - 4-bit loop counter, initialized by MAXC

Programmer-visible registers used:
  AX, DX       - for word multiply/divide
  AH, AL       - for byte multiply/divide

ALU OPERATIONS USED
-------------------
RCL (Rotate through Carry Left):
  For a 16-bit value: the 16 bits plus the carry flag form a 17-bit ring.
  The top bit shifts into CF, and the old CF shifts into the bottom bit.
  For byte operations: 8 bits plus CF form a 9-bit ring.

RCR (Rotate through Carry Right):
  Opposite direction. Bottom bit shifts into CF, old CF shifts into top bit.
  For byte operations: 8 bits plus CF form a 9-bit ring.

NEG (Negate / Two's Complement):
  Computes the two's complement: result = 0 - operand.
  Sets CF=1 if operand != 0, CF=0 if operand == 0.

COM1 (One's Complement):
  Flips all bits: result = ~operand (bitwise NOT).
  Does NOT affect flags.

ADD:
  result = tmpA + tmpB. Sets CF on carry out.

SUBT (Subtract):
  result = tmpA - tmpB. Sets CF if borrow (tmpA < tmpB for unsigned).

PASS:
  result = operand unchanged. Sets Zero flag.

INC:
  result = operand + 1.

MAXC:
  Initializes CNT to 15 for word operations, 7 for byte operations.

NCZ (Not Counter Zero):
  Decrements CNT. If CNT was non-zero before decrement, the condition is true
  (jump taken). If CNT was zero, condition is false (fall through).

WORD vs BYTE OPERATIONS
------------------------
For byte operations, tmpA and tmpC are treated as 8-bit registers (low byte only).
RCL/RCR operate on 8 bits + carry (9-bit ring) instead of 16 bits + carry.
MAXC initializes the counter to 7 instead of 15.
The loop thus executes 8 times for bytes, 16 times for words.

=============================================================================
CORX - Core Multiply Routine
=============================================================================
Entry: tmpC = multiplier, tmpB = multiplicand
Exit:  tmpA:tmpC = 32-bit product (tmpA = high word, tmpC = low word)

Algorithm (pseudocode):
  1. tmpA = 0
  2. Rotate tmpC right through carry (RCR). This puts the low bit of tmpC
     into CF, and shifts tmpC right by 1.
  3. Initialize counter: CNT = 15 (word) or 7 (byte)
  4. LOOP (starting from step 5):
  5.   If CF == 1: tmpA = tmpA + tmpB  (add multiplicand to accumulator)
  6.   Rotate tmpA right through carry (RCR). This shifts the sum right.
  7.   Rotate tmpC right through carry (RCR). This picks up the bit shifted
       out of tmpA (via CF) and shifts the next multiplier bit into CF.
  8.   Decrement CNT. If CNT != 0, go to step 5.
  9. Return. Result is in tmpA (high word) and tmpC (low word).

Note: In step 5, the ADD updates CF. In steps 6-7, the RCR operations rotate
through CF, propagating the carry/sum bit from tmpA into tmpC, and extracting
the next multiplier bit from tmpC into CF.

For byte operations: steps 6-7 operate on 8-bit values. The final result is
split across the low bytes of tmpA and tmpC.

=============================================================================
CORD - Core Divide Routine
=============================================================================
Entry: tmpA = high word of dividend, tmpC = low word of dividend,
       tmpB = divisor
Exit:  tmpA = remainder, tmpC = COMPLEMENTED quotient (one's complement)

The quotient stored in tmpC is the bitwise complement of the actual quotient.
The caller must apply COM1 (one's complement) to get the real quotient.

Algorithm (pseudocode):
  1. Compare: result = tmpA - tmpB (SUBT), set flags, discard result
  2. Initialize counter: CNT = 15 (word) or 7 (byte)
  3. If CF == 0 (no borrow, meaning tmpA >= tmpB): overflow/divide-by-zero
     → generate INT 0 (divide error)
  4. LOOP (starting from step 5):
  5.   Rotate tmpC left through carry (RCL). The old CF (quotient bit from
       previous iteration) shifts into the bottom of tmpC.
  6.   Rotate tmpA left through carry (RCL). The top bit of tmpA shifts into
       CF. This provides the "17th bit" for the subtraction.
  7.   Set up subtraction: prepare SUBT tmpA (i.e., tmpA - tmpB)
  8.   If CF == 1 (top bit of tmpA was set, meaning we definitely can subtract):
       → Go to step 13 (subtract path)
  9.   Perform the comparison: result = tmpA - tmpB, update flags, discard result
  10.  If CF == 0 (no borrow, tmpA >= tmpB): go to step 14 (subtract path)
  11.  Decrement CNT. If CNT != 0, go to step 5. Otherwise continue to step 12.
  12.  (Done) Rotate tmpC left through carry (RCL) to pick up last quotient bit.
       Rotate tmpC left again (RCL) but discard result (puts top bit of tmpC
       into CF for later use by POSTIDIV). Return.
  13.  Reset carry: CF = 0
  14.  Subtract: tmpA = tmpA - tmpB (store the SUBT result into tmpA).
       Decrement CNT. If CNT != 0, go to step 5. Otherwise go to step 12.

IMPORTANT: The carry flag behavior during the loop is crucial:
  - After step 9 (comparison without subtract): CF=1 means tmpA < tmpB (borrow),
    so we do NOT subtract. The CF=1 is the complemented quotient bit (actual
    quotient bit would be 0). CF=0 means tmpA >= tmpB, so we DO subtract.
  - After step 13-14 (subtract path): CF is explicitly reset to 0. This 0
    becomes the complemented quotient bit (actual quotient bit would be 1).
  - In step 5, the CF is rotated into the bottom of tmpC, building up the
    complemented quotient.

The net effect: tmpC accumulates the ONE'S COMPLEMENT of the quotient.

=============================================================================
TOP-LEVEL MICROCODE: UNSIGNED WORD MULTIPLY (MUL rmw)
=============================================================================
  1. tmpC = AX             ; load multiplier
  2. tmpB = source_operand ; load multiplicand
  3. CALL CORX             ; perform multiplication
  4. AX = tmpC             ; store low word of result
  5. DX = tmpA             ; store high word of result
  6. CALL MULCOF           ; set CF and OF flags

=============================================================================
TOP-LEVEL MICROCODE: UNSIGNED BYTE MULTIPLY (MUL rmb)
=============================================================================
  1. tmpC = AL             ; load multiplier (byte)
  2. tmpB = source_operand ; load multiplicand (byte)
  3. CALL CORX             ; perform multiplication (8-bit mode)
  4. AL = tmpC             ; store low byte of result
  5. AH = tmpA             ; store high byte of result
  6. CALL MULCOF           ; set CF and OF flags

=============================================================================
TOP-LEVEL MICROCODE: UNSIGNED WORD DIVIDE (DIV rmw)
=============================================================================
  1. tmpA = DX             ; high word of dividend
  2. tmpC = AX             ; low word of dividend
  3. tmpB = source_operand ; divisor
  4. CALL CORD             ; perform division
  5. COM1 tmpC             ; complement tmpC to get actual quotient
  6. AX = ~tmpC            ; store quotient (one's complement of tmpC)
  7. DX = tmpA             ; store remainder

=============================================================================
TOP-LEVEL MICROCODE: UNSIGNED BYTE DIVIDE (DIV rmb)
=============================================================================
  1. tmpA = AH             ; high byte of dividend
  2. tmpC = AL             ; low byte of dividend
  3. tmpB = source_operand ; divisor (byte)
  4. CALL CORD             ; perform division (8-bit mode)
  5. COM1 tmpC             ; complement tmpC
  6. AL = ~tmpC            ; store quotient (low byte)
  7. AH = tmpA             ; store remainder (low byte)

=============================================================================
MULCOF - Set flags after unsigned multiply
=============================================================================
  If tmpA (high word/byte of result) is non-zero:
    CF = 1, OF = 1
  Else:
    CF = 0, OF = 0

=============================================================================
SIGNED MULTIPLY AND DIVIDE
=============================================================================

PREIMUL - Pre-processing for signed multiply (IMUL)
----------------------------------------------------
Entry: tmpC = multiplier, tmpB = multiplicand
  1. Test sign of tmpC: rotate left through carry to get sign bit into CF
  2. If CF == 1 (tmpC is negative):
       tmpC = NEG(tmpC)    ; negate to make positive
       F1 = ~F1            ; toggle F1
  3. Test sign of tmpB: rotate left through carry
  4. If CF == 1 (tmpB is negative):
       tmpB = NEG(tmpB)    ; negate to make positive
       F1 = ~F1            ; toggle F1

After PREIMUL: both operands are positive, F1 indicates if result should be
negated (F1=1 means result is negative).

PREIDIV - Pre-processing for signed divide (IDIV)
--------------------------------------------------
Entry: tmpA:tmpC = dividend (32-bit signed), tmpB = divisor
  1. Test sign of tmpA: rotate left through carry to get sign bit into CF
  2. If CF == 1 (dividend is negative):
       Negate the 32-bit value tmpA:tmpC (two-word negation):
         tmpC = NEG(tmpC)
         If CF == 1 (tmpC was non-zero): tmpA = COM1(tmpA)  ; one's complement
         Else (tmpC was zero): tmpA = NEG(tmpA)             ; two's complement
       F1 = ~F1            ; toggle F1
  3. Test sign of tmpB: rotate left through carry
  4. If CF == 1 (tmpB is negative):
       tmpB = NEG(tmpB)    ; negate to make positive
       F1 = ~F1            ; toggle F1

NEGATE - Negate 32-bit result (shared by IMUL and IDIV)
-------------------------------------------------------
Called when F1 == 1 (result should be negative).
Entry: tmpA:tmpC = result
  1. tmpC = NEG(tmpC)
  2. If CF == 1 (from NEG): tmpA = COM1(tmpA)   ; one's complement
     Else: tmpA = NEG(tmpA)                     ; two's complement
  3. F1 = ~F1

POSTIDIV - Post-processing for signed divide (IDIV)
----------------------------------------------------
Called after CORD and COM1 for signed division.
Entry: tmpA = remainder, tmpC = complemented quotient, tmpB = original DX
       (upper word of original dividend, loaded by caller before this call)
  1. Check overflow: the top bit of the complemented quotient was placed in CF
     by CORD. If CF == 0 (meaning top bit of actual quotient is 1), the quotient
     is too large for a signed value → generate INT 0 (divide error).
  2. Test sign of tmpB (original upper dividend): rotate left through carry
  3. If CF == 1 (original dividend was negative):
       tmpA = NEG(tmpA)    ; negate remainder
  4. If F1 == 1 (quotient should be negative):
       tmpC = tmpC + 1     ; INC converts from 1's complement to 2's complement
       (The caller's COM1 already complemented; INC completes the 2's complement)
  5. Else (F1 == 0, quotient should be positive):
       tmpC = COM1(tmpC)   ; complement to get positive quotient
       (This undoes the complemented quotient from CORD)
  6. Clear CF and OF.

IMULCOF - Set flags after signed multiply
------------------------------------------
  The upper half is significant if it is NOT the sign extension of the lower half.
  1. Set tmpB = 0
  2. Rotate tmpC left through carry to get top bit of tmpC into CF
  3. Compute tmpA + tmpB + CF (ADC: add with carry). If result is zero, the
     upper half is just sign extension.
  4. If result == 0: CF=0, OF=0
     Else: CF=1, OF=1

=============================================================================
TWO-WORD NEGATION DETAILS
=============================================================================
To negate a 32-bit value split across tmpA (high) and tmpC (low):
  1. NEG tmpC: computes 0 - tmpC.
     - If tmpC was 0: result is 0, CF = 0
     - If tmpC was non-zero: result is two's complement, CF = 1
  2. Based on CF from step 1:
     - If CF == 1: tmpA = COM1(tmpA) = ~tmpA (one's complement only)
     - If CF == 0: tmpA = NEG(tmpA) (full two's complement)

Mathematical justification: For a 32-bit value V = tmpA*2^16 + tmpC:
  -V = (~tmpA)*2^16 + (~tmpC + 1) when tmpC != 0 (carry doesn't propagate)
  -V = (~tmpA + 1)*2^16 + 0        when tmpC == 0 (carry propagates to high word)

=============================================================================
SIGNED OVERFLOW DETECTION IN IDIV
=============================================================================
For unsigned DIV: overflow is detected at CORD entry by checking if
tmpA >= tmpB. If so, the quotient won't fit in 16 bits (or 8 bits for byte).

For signed IDIV: after converting operands to positive and performing unsigned
division via CORD, POSTIDIV checks if the quotient fits in a signed value.
The top bit of the complemented quotient (left in CF by CORD) is checked:
if CF == 0, the top bit of the actual quotient is 1, meaning the unsigned
quotient >= 0x8000, which can't be represented as a positive signed value
(or its negation would be < -32767). This triggers a divide error.

Note: This makes the signed overflow check slightly stricter than necessary.
A quotient of -32768 would fit in a 16-bit signed value but the 8086
considers it an overflow.
