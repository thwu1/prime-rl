The OpenROAD EDA project uses a Tcl-based regression system (`/app/tcl_source/flow_metrics.tcl`) to validate physical design flow results. It defines 22 metrics with comparison operators and tolerance expressions, computes limits from golden reference values, and checks actual run results against those limits. A key subtlety is the variable resolution mechanism in `save_metric_limits`: metric keys like `DRT::clock_period` are decomposed via regexp to create dynamically-scoped variables (e.g., `clock_period`) that tolerance expressions for other metrics reference.

Build `/app/metrics_engine.py` — a Python module and CLI that faithfully replicates this Tcl system's behavior with exact numeric fidelity. You must also generate `/app/metric_defs.json` capturing the extracted metric definitions and variable mappings in a structured format.

The module must expose three classes (`ExpressionEvaluator`, `MetricsChecker`, `RegressionAnalyzer`) and three CLI subcommands (`limits`, `check`, `analyze`) that accept a `--defs` flag for custom metric definitions. Golden references and run data are under `/app/designs/`. The Tcl source is the authoritative specification; tests at `/tests/test_state.py` define the exact interface and verify correctness.
