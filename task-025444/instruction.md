`/app/pipeline/` contains a 4-module Python scoring pipeline (`ingest.py`, `analyze.py`, `metrics.py`, `export.py`) implementing the OWASP Benchmark tool evaluation methodology. It ingests ground-truth expected results and SAST tool scan findings from `/app/data/`, classifies each tool's detection accuracy per vulnerability category (TP/FN/FP/TN) using CWE matching with configurable tool-prefix-based exceptions, computes per-category rates and macro-averaged overall metrics, ranks tools by Youden's J statistic, and exports a scorecard.

Running `bash /app/run_pipeline.sh` fails or produces incorrect output due to multiple interacting bugs across its modules affecting data ingestion integrity, schema conformity, CWE exception matching semantics, statistical aggregation methodology, output ordering, and pipeline completeness.

`/app/reference_scorecard.json` is a scorecard produced by a previous analyst who attempted to score the tools independently. This reference scorecard itself contains errors — evaluate it against the authoritative specification and identify all discrepancies.

`/app/report_template.jq` is a jq filter intended to generate a summary report from the scorecard but has semantic errors that must be diagnosed and corrected.

Available resources:
- `/app/data/` — ground-truth expected results (`expected_results.csv`), 4 SAST tool scan results (`tool_results/*.jsonl`), and CWE exception configuration (`config.yaml`)
- `/app/schema.sql` — authoritative SQLite database schema with integrity constraints
- `/app/reference/BenchmarkScore.java` — excerpt of OWASP's authoritative scoring engine defining `compare()`, `calculateScores()`, and `calculateMetrics()` algorithms
- `/app/output_schema.json` — required JSON output format specification
- `/app/audit_query.sql` — SQL query for audit CSV generation

Produce all of the following:
1. `/app/benchmark.db` — SQLite database initialized from `/app/schema.sql` with all 6 tables correctly populated (expected_results, tools, findings, classifications, category_metrics, overall_metrics)
2. `/app/output/scorecard.json` — valid JSON conforming to `/app/output_schema.json`
3. `/app/output/audit.csv` — generated by executing `/app/audit_query.sql` against the populated database
4. `/app/output/summary_report.json` — generated by applying the corrected `/app/report_template.jq` filter to the scorecard using `jq`
5. `/app/output/evaluation.json` — forensic evaluation of `/app/reference_scorecard.json` identifying all discrepancies from the correct scorecard. Must be a JSON object containing: `incorrect_tools` (list of tool names with errors), `discrepancies` (list of `{"tool", "category", "field", "reference_value", "correct_value"}` objects), and `root_cause` (string explaining the underlying cause of the errors)
