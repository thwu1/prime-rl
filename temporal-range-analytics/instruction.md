The database application at `/app/` tracks server allocations across datacenters. PostgreSQL is installed but stopped; database `taskdb` does not exist yet. Loading `/app/setup.sql` into `taskdb` populates the source tables. Examine the schema and data to understand the model.

Four SQL files under `/app/queries/` must each produce correct results when run with `psql -U postgres -d taskdb -f <file>`. Some contain broken implementations; others are incomplete. Diagnose all issues and deliver working queries.

**`/app/queries/migration.sql`** must create and populate table `allocations`. Each source row represents a server beginning a new project assignment; the assignment's validity spans from its event date until the same server's next event, or `2024-01-01` for the final event. Bounds are `[)`. The table must prevent any server from having temporally overlapping assignments. Columns: `server_id text`, `datacenter text`, `project_id int` (FK to `projects`), `validity daterange`, `daily_cost numeric(10,2)`. Expected: 37 rows.

**`/app/queries/streaks.sql`** must return the top 5 servers ranked by their longest run of chronologically consecutive allocations where daily cost never decreases between successive entries (ties broken by `server_id` ascending). Columns: `server_id`, `streak_length` (int), `streak_start` (date), `streak_end` (date) -- dates are the lower validity bounds of the run's first and last allocations.

**`/app/queries/project_rollup.sql`** must report all 12 projects with hierarchical aggregation. Columns: `project_name text`, `depth int` (0 at root), `path text` (ancestor chain root-to-leaf joined by ` > `), `own_server_days int` (days from allocations directly assigned to this project; 0 if none), `total_server_days int` (own plus all descendants' days). Order by `path`.

**`/app/queries/utilization_report.sql`** must compute total cost (days of overlap multiplied by daily rate) for every combination of datacenter and quarter, plus per-datacenter subtotals, per-quarter subtotals, and a grand total. Quarters: `Q1 2023` through `Q4 2023` spanning `[2023-01-01, 2024-01-01)` in 3-month intervals. Only days where an allocation's validity intersects a quarter count toward cost. Columns: `datacenter text`, `quarter text`, `total_cost numeric`. NULL indicates aggregation across that dimension. Expected: 15 rows. Order: `datacenter NULLS LAST, quarter NULLS LAST`.
