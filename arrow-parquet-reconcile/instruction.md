A data pipeline writes hourly event batches as individual Parquet files to `/app/staging/`. Over several months, the pipeline's schema has evolved through multiple iterations and operational retries have produced duplicate ingestions. The staging directory now contains files with heterogeneous Arrow schemas — differing column sets, type widths, timestamp precisions, timezone awareness, encoding strategies, and numeric representations — as well as overlapping records across files.

The data contract at `/app/data_contract.md` defines the target output schema, deduplication semantics, data quality requirements, and output format specifications. It specifies WHAT the output must look like but not HOW to reconcile the diverse source schemas — you must analyze each file's Arrow schema and determine the necessary type promotions, encoding conversions, timezone handling, and missing-column strategies yourself.

Compact the staging data into a clean, deduplicated, Hive-partitioned Parquet dataset at `/app/output/compacted/`, a quarantine file at `/app/output/quarantine.parquet` for records violating data quality rules, and a compaction manifest at `/app/output/manifest.json`.
