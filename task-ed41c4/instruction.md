Build an ETL pipeline at `/app/` that transforms FHIR R4 Bundle JSON data from `/app/data/` into a SQLite analytics database at `/app/analytics.db` and generates an analytics report at `/app/output/report.json`.

Running `bash /app/run.sh` must execute the complete pipeline. The pipeline must use `jq` to extract and flatten FHIR resources from bundles into per-resource-type NDJSON files written to `/app/intermediate/`, then load the flattened data into SQLite tables defined by `/app/table_schemas.sql`, execute analytics queries, and produce the report conforming to `/app/schema.json`.

The analytics section of the report must include: observations-per-patient counts with family names, patients who have both an active Condition and an active MedicationRequest, average observation values grouped by LOINC code, count of vital-signs category observations, medication request status distribution, patients missing a `managingOrganization` reference, observation effective date range (earliest/latest as YYYY-MM-DD), and observations with values exceeding clinical thresholds defined in `/app/thresholds.json`.

The FHIR R4 data uses choice-type polymorphism (`valueQuantity` for `value[x]`, `medicationCodeableConcept` or `medicationReference` for `medication[x]`), contained resources with fragment references (`#id`) that must be resolved to extract medication display names, CodeableConcept/Coding nested structures, date-times at varying precisions that must be normalized to date-only, and mixed reference formats (relative, URN, fragment). Refer to `/app/spec_notes.md`.
