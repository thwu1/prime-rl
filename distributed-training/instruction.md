A simulation framework at `/app/lib.py` models multi-GPU distributed training using asyncio. It tracks simulated time and peak memory without requiring actual GPUs. The framework depends on a native cost model module (`/app/cost_model.py`) that does not yet exist — it must be generated by compiling and running the C-based tool at `/app/native/` against the binary hardware spec `/app/native/hw_spec.bin`.

Strategy configurations (ranks, layers, batches, time and memory budgets) are stored in the SQLite database `/app/cluster.db`. The pipeline parallelism topology is described in `/app/topology.json`.

Three async training strategy functions must be implemented in `/app/strategies.py`:

| Strategy | Description |
|---|---|
| `ddp` | Distributed Data Parallel |
| `fsdp` | Fully Sharded Data Parallel (ZeRO-3) |
| `pipeline_fsdp` | Pipeline Parallelism combined with FSDP |

Each function receives a pre-configured `Model` instance and must produce correct, trained weights within the time and memory budgets defined in the cluster database. Call `model.set_final_weight(layer, weight)` for every layer before returning. Correctness is verified by `Model.check()`, which ensures all layers have complete, step-1 weights when combining shards across all ranks.

Study `/app/lib.py` to understand the full `Model` API, its assertions, and timing/memory accounting. Memory is tracked via five storage dictionaries on the Model — only objects stored in these dicts count toward memory, and deleting entries frees simulated memory.
