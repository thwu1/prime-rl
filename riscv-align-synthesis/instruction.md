The directory `/app/` contains a Python implementation of ELF alignment relocation synthesis for the linker's relocatable mode (`ld -r`). The pipeline parses ROB binary test files (`/app/objects/`), determines whether `R_RISCV_ALIGN` or `R_LARCH_ALIGN` relocations should be synthesized at input section boundaries, and merges sections with correct alignment padding.

A recent refactoring introduced regressions in the binary parser (`/app/rob_parser.py`) and the synthesis engine (`/app/synth_engine.py`). The pipeline runs without exceptions on all test scenarios -- `/app/cli.py test` reports success -- but produces incorrect synthesis decisions for a subset of cases. The bugs span two components and interact: a parser defect silently corrupts relocation metadata in a way that happens to produce correct-looking synthesis output for most files, while two independent synthesis logic errors affect different architectures and alignment patterns. Fixing the synthesis approach alone will accidentally mask the parser bug for synthesis-level checks, but a direct parser assertion will still fail.

The format specification is at `/app/rob_format.md`, the synthesis specification (including two competing suppression strategies and a concrete disambiguating scenario) is at `/app/spec.md`, and type definitions are in `/app/elf_defs.py`. The section merger (`/app/merger.py`) is correct and should not be modified. Use `xxd` to cross-verify the parser's interpretation of binary data against the raw ROB file contents, and `/app/cli.py inspect <file>` to examine parsed structures.

Debug and fix all regressions so the implementation correctly handles: weak vs strong assembler-emitted ALIGN suppression, REL vs RELA relocation format distinction, architecture-specific alignment thresholds (RISC-V vs LoongArch), and multi-section merging with mixed alignment requirements.
