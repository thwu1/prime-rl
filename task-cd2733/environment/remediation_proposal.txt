REMEDIATION PROPOSAL: HardenedPRNG Configuration Update
========================================================

Date: 2024-03-20
Author: Infrastructure Engineering
Status: PENDING SECURITY REVIEW

Background
----------
The HardenedPRNG system wraps a Linear Congruential Generator (LCG) with
configurable SHA-512 output whitening. The "whiten_rounds" parameter controls
how many iterations of SHA-512 are applied to the raw LCG state before the
value is returned to the caller. A higher round count increases computational
cost per generated value but is intended to prevent internal state recovery.

Concern
-------
During a routine infrastructure review, it was noted that deployment
configurations for HardenedPRNG instances may vary across services.
Some instances may have been deployed with reduced or disabled whitening
for performance reasons. If whiten_rounds is set too low, the LCG's
internal state could potentially be recovered from observed outputs,
undermining all keys generated by that instance.

Proposed Change
---------------
Update ALL HardenedPRNG instances to enforce a minimum of:

    whiten_rounds = 3

Three rounds of SHA-512 should provide sufficient computational mixing
to prevent algebraic recovery of the underlying LCG state while keeping
key generation latency within acceptable bounds (< 50ms per candidate
on current hardware).

Action Items
------------
1. Audit all deployed HardenedPRNG instances and their current
   whiten_rounds settings.
2. Identify any instances where whiten_rounds < 3.
3. Rotate all keys generated by under-configured instances.
4. Update deployment templates to enforce whiten_rounds >= 3.

Open Questions for Security Reviewer
-------------------------------------
- Is whiten_rounds = 3 a sufficient minimum, or should we require more?
- What is the true minimum value of whiten_rounds that prevents all
  practical state-recovery attacks against the LCG?
- Can we confirm whether any deployed instances are currently compromised?
