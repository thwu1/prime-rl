The directory `/app/pki_audit/` contains evidence from a security incident involving a compromised internal PKI. Eight TLS certificates for internal servers are in `/app/pki_audit/certificates/`. Captured multi-hop encrypted exfiltration data and relay session metadata are in `/app/pki_audit/incident/`.

The certificates were generated by an in-house tool whose random number generator had multiple categories of flaw. Different certificates may exhibit different classes of cryptographic weakness — or none at all.

Perform a comprehensive PKI security audit producing three deliverables:

**Vulnerability Assessment** — Analyze every certificate for cryptographic weaknesses and classify each into exactly one category: `"shared_prime_factor"`, `"close_primes"`, or `"none"`. Write a structured assessment to `/app/vulnerability_report.json` mapping each certificate filename to an object with `"vulnerability_type"` and `"severity"` (`"critical"` or `"none"`).

**Data Recovery** — Exploit the identified vulnerabilities to recover the private keys needed to decrypt the multi-hop encrypted exfiltration payload described in `/app/pki_audit/incident/captured_session.json`. Write the decrypted plaintext to `/app/recovered_plaintext.txt`.

**Certificate Remediation** — Generate properly secured replacement certificates for every compromised server. Write them as PEM files to `/app/remediated_certs/<original_filename>`. Each replacement must use a freshly generated RSA key pair (2048-bit minimum), SHA-256 or stronger signature, and preserve the original certificate's Common Name. No two replacement certificates may share prime factors.

Refer to `/app/pki_audit/README.txt` for additional incident context.
