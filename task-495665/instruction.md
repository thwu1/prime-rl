The file `/app/game.py` implements a tour optimization problem: a TSP variant with time windows and a strict no-waiting constraint. A tourist visits sites on a 100×100 grid, collecting value rewards. Each site has coordinates (avenue, street), a visit duration, a value, and a time window [begin\_hour, end\_hour] (hours; internally computed in minutes). Travel between consecutive sites costs Manhattan-distance minutes. The first site in a tour is entered at its opening time; for all subsequent sites, the arrival time (previous departure + travel time) must fall at or after the site's opening — early arrivals invalidate the entire tour. Each visit must also complete before the site's closing time.

The tool `glpsol` (GLPK's mixed-integer programming solver) is available at `/usr/bin/glpsol`. Build a solver pipeline that uses GLPK for the core combinatorial optimization.

Create:
- `/app/touring.mod` — a GMPL (GNU MathProg Language) model formulating the touring problem as a mixed-integer program. The model must declare a set `SITES`, read instance parameters (avenue, street, duration, value, begin\_min, end\_min) from a `.dat` data file, encode site-selection and sequencing decisions with binary flow variables, enforce time-window and no-waiting constraints via arrival-time variables with big-M bounds, solve the MIP, and write the solution (selected sites, arcs, first site) to `/tmp/glpk_sol.txt` via `printf` redirection.
- `/app/solver.py` — a Python module exporting `solve(sites_data)` that accepts the instance dict (mapping integer site IDs to property dicts with keys `'avenue'`, `'street'`, `'duration'`, `'value'`, `'begin_hour'`, `'end_hour'`), generates `.dat` files compatible with the GMPL model, invokes `glpsol` on `/app/touring.mod`, parses the solution output to reconstruct the tour, and returns an ordered list of integer site IDs.

Study `/app/game.py` to understand the exact constraint semantics — particularly the no-waiting rule and how the first site's start time is determined. The solver is evaluated on 8 test instances (60 sites each). Every tour must be valid with individual score ≥ 800. The aggregate score across all instances must be ≥ 10000.
