A district election used the SecureVote cryptosystem (RSA-based) to encrypt and store 30 voters' ballots. The system has been flagged for a security audit after concerns about its key generation process. Your task has two parts.

## Part 1 — Decrypt the ballots

Voter RSA public keys are stored as PEM files in `/app/keys/` (one per voter, e.g. `/app/keys/V001.pem`). Voter enrollment data and encrypted ballots are in the SQLite database at `/app/election.db` (tables: `voters`, `ballots`, `election_meta`). The cryptosystem source code is at `/app/election_system.py`. An operational audit log at `/app/audit.log` contains key generation metadata including seeds and timestamps.

Three different key generation methods were used for three batches of voters. Identify the cryptographic weakness in each method, exploit it to factor all 30 RSA public keys, and decrypt every vote.

## Part 2 — Evaluate proposed remediations

Five proposed patches to the key generation system are in `/app/patches/` (`patch_A.py` through `patch_E.py`). Each patch includes test keys generated by that method in `/app/patches/test_keys/{A..E}/` (three PEM key files per patch). Analyze each patch's code and its test keys to determine whether the remediation is **SECURE** or still **VULNERABLE**.

## Output

Write results to `/app/results.json`:

```json
{
  "tally": {"CandidateName": count, ...},
  "votes": {"V001": "CandidateName", "V002": "CandidateName", ...},
  "patch_assessment": {"A": "SECURE", "B": "VULNERABLE", ...}
}
```

The file must contain the correct tally, the correct individual vote for each of the 30 voters (V001–V030), and the correct security verdict for each of the 5 patches. Candidate names must match those in the election metadata exactly.
