The East DC primary (server_id 1001) continued accepting writes for 43 seconds before connectivity was restored. Meanwhile, an Orchestrator Raft quorum in the West DC promoted a local replica as a new primary (server_id 2001), which then accepted writes for approximately 38 minutes before engineers intervened.

Both data centers now contain writes absent from the other. The database `github_meta` on the local MySQL instance contains the base state — the last consistent snapshot before the partition. Decoded ROW-format binary log extracts from each DC are at `/app/binlogs/east_dc.binlog.txt` and `/app/binlogs/west_dc.binlog.txt`. Incident metadata and conflict resolution rules are in `/app/metadata.json`. The table schema is at `/app/schema.sql` — you will need it to map the column ordinal references (`@1`, `@2`, ...) in the ROW-format events to actual column names, and to decode ENUM ordinals to their string values.

Parse both binary log extracts, identify all DML operations from each DC during the split-brain window, detect conflicting writes (same table + primary key modified on both sides), and resolve each conflict according to the rules in `/app/metadata.json`. Create a new database `github_meta_reconciled` containing the fully reconciled state: base data with all non-conflicting writes from both DCs applied and all conflicts correctly resolved. Write a JSON reconciliation report to `/app/reconciliation_report.json` with at minimum: `east_writes_count`, `west_writes_count`, `total_conflicts`, and a `conflicts` array describing each detected conflict and its resolution.
