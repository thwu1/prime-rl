# MiniStack-16 ISA Specification

## Overview

MiniStack-16 is a 16-bit stack-based virtual machine.

- **Word size**: 16 bits, two's complement representation for negative values
- **Byte order**: Little-endian
- **Memory**: 65536 bytes (64 KB), byte-addressable
- **Stack**: Separate stack of up to 256 16-bit values (not mapped into main memory)
- **Program counter (PC)**: 16-bit, starts at address 0x0000
- **Stack pointer (SP)**: Index into the stack array, starts at 0 (empty stack)

Programs are loaded into memory starting at address 0x0000. Execution begins at address 0x0000 and proceeds sequentially unless modified by a branch, jump, or halt instruction.

Results are truncated to 16 bits.

## Note on Reference Implementation

The pre-compiled binary programs in `/app/programs/` were generated by a reference implementation that is no longer available. Where this specification is ambiguous or underspecified, the behavior exhibited by these programs (as documented in `/app/expected/`) should be considered the canonical behavioral specification.

## Instruction Encoding

Each instruction begins with a 1-byte opcode. Some instructions are followed by a 2-byte (16-bit) operand in little-endian byte order. Instructions are therefore either 1 byte or 3 bytes long.

## Stack Convention

In the descriptions below, **a** denotes the value on top of the stack (TOS), and **b** denotes the value immediately below it (second element). "Pop a, b" means: first pop a (the top), then pop b (the new top).

## Instruction Reference

### Data Movement

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x01 | PUSH imm16 | 3 | Push the 16-bit immediate value onto the stack. The immediate is stored in the instruction stream in little-endian order. |
| 0x02 | POP | 1 | Discard the top element of the stack. |
| 0x03 | DUP | 1 | Push a copy of the top element onto the stack. |
| 0x04 | SWAP | 1 | Swap the top two elements: `... b a` becomes `... a b`. |
| 0x05 | OVER | 1 | Copy the second element to the top: `... b a` becomes `... b a b`. |

### Arithmetic

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x06 | ADD | 1 | Pop a, b. Push `(b + a) & 0xFFFF`. |
| 0x07 | SUB | 1 | Pop a, b. Push `(b - a) & 0xFFFF`. |
| 0x08 | MUL | 1 | Pop a, b. Push `(b * a) & 0xFFFF`. |
| 0x09 | DIV | 1 | Pop a, b. Push `b / a` (integer division). Error if a == 0. |
| 0x0A | MOD | 1 | Pop a, b. Push `b % a` (remainder after division). Error if a == 0. |

### Bitwise

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x0B | AND | 1 | Pop a, b. Push `b & a`. |
| 0x0C | OR | 1 | Pop a, b. Push `b \| a`. |
| 0x0D | XOR | 1 | Pop a, b. Push `b ^ a`. |
| 0x0E | NOT | 1 | Pop a. Push `~a` (bitwise complement). |
| 0x0F | NEG | 1 | Pop a. Push `-a` (two's complement negation). |

### Shifts

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x10 | SHL | 1 | Pop a, b. Push `b << (a & 0xF)`. Vacated bits are filled with zeros. |
| 0x11 | SHR | 1 | Pop a, b. Right shift: push `b >> (a & 0xF)`. Only the low 4 bits of the shift amount are used. |

### Comparison

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x12 | EQ | 1 | Pop a, b. Push 1 if `b == a`, else 0. |
| 0x13 | LT | 1 | Pop a, b. Push 1 if `b < a`, else 0. |
| 0x14 | GT | 1 | Pop a, b. Push 1 if `b > a`, else 0. |

### Control Flow

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x15 | JMP off16 | 3 | Unconditional jump. The 16-bit signed offset is read from the instruction stream (little-endian). After reading the offset, PC points to the byte after the JMP instruction. The offset is then added to PC: `PC = PC + (int16_t)off16`. An offset of 0 is a no-op (continues to the next instruction). An offset of -3 jumps back to this JMP instruction (infinite loop). |
| 0x16 | JZ off16 | 3 | Pop a. If `a == 0`, jump: `PC = PC + (int16_t)off16` (where PC has been advanced past this instruction). Otherwise, continue. |
| 0x17 | JNZ off16 | 3 | Pop a. If `a != 0`, jump: `PC = PC + (int16_t)off16` (where PC has been advanced past this instruction). Otherwise, continue. |
| 0x18 | CALL off16 | 3 | Push the return address (the PC value after this instruction, i.e., the address of the next instruction). Then jump: `PC = PC + (int16_t)off16`. |
| 0x19 | RET | 1 | Pop an address from the stack. Set `PC = popped_address`. |

### Memory Access

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x1A | LOAD | 1 | Pop addr. Read a 16-bit word from `memory[addr]` (little-endian: low byte at addr, high byte at addr+1). Push the value. |
| 0x1B | STORE | 1 | Pop addr. Pop val. Write val as a 16-bit word to `memory[addr]` (little-endian: low byte at addr, high byte at addr+1). |
| 0x1C | LOADB | 1 | Pop addr. Read a single byte from `memory[addr]`. Zero-extend to 16 bits and push. |
| 0x1D | STOREB | 1 | Pop addr. Pop val. Write `val & 0xFF` to `memory[addr]`. |

### I/O

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0x1E | PUTC | 1 | Pop a. Print `a & 0xFF` as an ASCII character to stdout. |
| 0x1F | PUTI | 1 | Pop a. Print `(int16_t)a` as a signed decimal integer to stdout (no trailing newline or space). |
| 0x20 | GETC | 1 | Read one byte from stdin. Push it as a 16-bit value (zero-extended). On EOF, push 0xFFFF (-1). |

### System

| Opcode | Mnemonic | Size | Description |
|--------|----------|------|-------------|
| 0xFF | HALT | 1 | Stop execution. The program exits successfully. |

## Assembly Syntax

The assembler accepts a simple text format:

- One instruction per line.
- Comments start with `#` or `;` and extend to end of line.
- Labels are identifiers followed by `:` on their own line.
- Immediate values can be decimal (e.g., `42`, `-5`) or hexadecimal (e.g., `0xFF`).
- For branch/jump instructions, the operand can be a label name (resolved to a relative offset by the assembler) or a numeric offset.
- Register names are not used (this is a stack machine).
- Mnemonics are case-insensitive.

Example:
```
    push 72     # ASCII 'H'
    putc
    push 10     # newline
    putc
    halt
```
