A PostgreSQL database (`/app/clubdata.sql`) has schema `cd` with tables `members` (31 rows, `recommendedby` for referral chains), `facilities` (9 rows, `membercost`/`guestcost`/`monthlymaintenance`), and `bookings` (~4000 rows, half-hour `slots`, `starttime`). 25 slots/day available per facility.

`/app/analytics.sql` defines five views and one stored function, all producing incorrect results. Set up PostgreSQL, load the data, then debug and fix all six components in `/app/analytics.sql`:

**`cd.daily_facility_revenue`** — Every (facility, date) from 2012-07-01 through 2013-01-31. Dates with no bookings must appear with revenue 0. Revenue = slots × guestcost (memid=0) or membercost. Columns: `facility_name`, `facid`, `date`, `revenue`. 1935 rows.

**`cd.revenue_rolling_stats`** — Per (facility, date) in Aug–Sep 2012. 15-day rolling window (current + 14 preceding) over daily revenue. Must incorporate July data for lookback even though output is restricted to Aug–Sep. Columns: `facility_name`, `facid`, `date`, `revenue`, `rolling_avg`, `rolling_stddev` (population standard deviation), `zscore` ((revenue − rolling_avg) / rolling_stddev; NULL when stddev is zero). 549 rows. Depends on `daily_facility_revenue`.

**`cd.member_network_stats`** — Downward referral tree per member. `direct_referrals`: count at depth 1 only. `total_network_size`: all transitive descendants. `max_depth`: longest chain. `network_revenue`: total booking revenue generated by all descendants (using guestcost for memid=0, membercost otherwise). Zero for members with no referrals. Columns: `memid`, `firstname`, `surname`, `direct_referrals`, `total_network_size`, `max_depth`, `network_revenue`. 31 rows.

**`cd.facility_monthly_analysis`** — Monthly per-facility metrics for months with bookings. `utilization_pct`: slots_used / (25 × actual days in that calendar month) × 100, rounded to 1 decimal. `revenue_rank`: RANK by revenue DESC within month. `prev_month_revenue`: LAG per facility across months. `growth_pct`: ((curr − prev) / prev) × 100, 1 decimal; NULL when no previous month. `category`: NTILE(3) by revenue per month → 'high'/'medium'/'low'. Columns: `facility_name`, `month`, `total_revenue`, `utilization_pct`, `revenue_rank`, `prev_month_revenue`, `growth_pct`, `category`. 28 rows.

**`cd.booking_anomaly_report`** — For each (facility, date) in Aug–Sep 2012 where |zscore| > 1.5 from `revenue_rolling_stats`: identify anomalous revenue days and the dominant booker (member contributing most revenue that day for that facility; ties broken by lowest memid; display 'GUEST' for memid=0, otherwise firstname || ' ' || surname). Columns: `facility_name`, `facid`, `date`, `revenue`, `zscore`, `anomaly_type` ('spike' if zscore > 0, 'dip' if < 0), `dominant_booker`, `dominant_pct` (booker's share of daily revenue as percentage, 1 decimal; NULL if revenue = 0). Depends on `revenue_rolling_stats`.

**`cd.member_value_score(p_memid INT) RETURNS NUMERIC`** — Returns `ROUND((direct_revenue + 0.5 × network_revenue) / GREATEST(tenure_months, 1), 2)`. `direct_revenue`: member's own booking revenue (guestcost for memid=0, membercost otherwise). `network_revenue`: from `member_network_stats`. `tenure_months`: complete months from member's `joindate` to `2013-02-01`. Depends on `member_network_stats`.
