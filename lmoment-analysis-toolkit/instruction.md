A flood analysis system at `/app/` estimates 100-year return levels for three river gauge stations. It chains a shell extraction layer (`/app/pipeline/extract.sh`) that reads station configs from `/app/data/stations.json` and uses `jq`/`awk` to extract flow measurements from CSV files, through a Python layer (`/app/analysis/lmoments.py`, `/app/analysis/fit.py`) implementing Hosking (1990, 1997) PWM-based L-moment estimators and GEV fitting via method of L-moments. The orchestrator (`/app/run_analysis.py`) also invokes a distribution selection module (`/app/analysis/distselect.py`) that should use L-moment ratio diagram theory to compare candidate extreme value distributions (GEV, Generalized Logistic, Generalized Pareto) and provide bootstrap confidence intervals for the return levels.

The pipeline currently fails. There are bugs in the data extraction, the L-moment estimator, and the GEV parameter convention. Additionally, the distribution selection module contains only unimplemented stub functions that must be completed using appropriate L-moment ratio diagram theory (Hosking & Wallis 1997).

Fix the bugs and implement the distribution selection module so that `python3 /app/run_analysis.py` produces `/app/output/return_levels.json` where every station includes: correct GEV location, scale, and shape parameters; correct 100-year return level; distribution selection results with sample L-moment ratios (tau3, tau4), per-candidate L-moment ratio diagram distances, and the best-fit distribution; and bootstrap confidence intervals for the 100-year return level.
