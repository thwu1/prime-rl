Normative Reference: C++17 Elementary String Conversions
(Excerpted from P0067R5, as amended by P0682R1)

== chars_format ==

  enum class chars_format {
      scientific = /*unspecified*/,
      fixed      = /*unspecified*/,
      hex        = /*unspecified*/,
      general    = fixed | scientific
  };

  The type chars_format is a bitmask type with elements scientific, fixed,
  and hex.

== to_chars (integer) ==

  to_chars_result to_chars(char* first, char* last, T value, int base = 10);

  Requires: base has a value between 2 and 36 (inclusive).

  Effects: The value of value is converted to a string of digits in the
  given base (with no redundant leading zeroes). Digits in the range
  10..35 (inclusive) are represented as lowercase characters a..z.
  If value is less than zero, the representation starts with a minus sign.

  If the member ec of the return value is equal to value-initialized errc,
  the conversion was successful and the member ptr is the one-past-the-end
  pointer of the characters written. Otherwise, the member ec has the
  value errc::value_too_large, the member ptr has the value last, and the
  contents of the range [first, last) are unspecified.

== to_chars (floating-point, shortest) ==

  to_chars_result to_chars(char* first, char* last, float value);
  to_chars_result to_chars(char* first, char* last, double value);

  Effects: value is converted to a string in the style of printf in the
  "C" locale. The conversion specifier is f or e, chosen according to the
  requirement for a shortest representation; a tie is resolved in favor
  of f.

  The string representation consists of the smallest number of characters
  such that there is at least one digit before the radix point (if present)
  and parsing the representation using the corresponding from_chars function
  recovers value exactly.

  [Note: This guarantee applies only if to_chars and from_chars are
  executed on the same implementation.]

  If there are several such representations, the representation with the
  smallest difference to the floating-point argument value is chosen,
  resolving any remaining ties using rounding according to
  round_to_nearest.

== to_chars (floating-point, formatted) ==

  to_chars_result to_chars(char* first, char* last, T value,
                           chars_format fmt);

  The functions taking a chars_format parameter determine the conversion
  specifier for printf as follows: The conversion specifier is
    f  if fmt is chars_format::fixed,
    e  if fmt is chars_format::scientific,
    a  (without leading "0x" in the result) if fmt is chars_format::hex,
    g  if fmt is chars_format::general.

  Without a precision parameter, these functions ensure that the string
  representation consists of the smallest number of characters such that
  parsing the representation using the corresponding from_chars function
  recovers value exactly (same shortest-representation guarantee as the
  default overload, restricted to the chosen format).

  to_chars_result to_chars(char* first, char* last, T value,
                           chars_format fmt, int precision);

  Effects: value is converted to a string in the style of printf in the
  "C" locale with the given precision.

== from_chars (integer) ==

  from_chars_result from_chars(const char* first, const char* last,
                               T& value, int base = 10);

  All functions named from_chars analyze the string [first, last) for a
  pattern, where [first, last) is required to be a valid range. If no
  characters match the pattern, value is unmodified, the member ptr of
  the return value is first and the member ec is equal to
  errc::invalid_argument.

  [Note: If the pattern allows for an optional sign, but the string has
  no digit characters following the sign, no characters match the
  pattern.]

  If the parsed value is not in the range representable by the type of
  value, value is unmodified and the member ec of the return value is
  equal to errc::result_out_of_range. The member ptr points to the first
  character not matching the pattern, or has the value last if all
  characters match.

  Otherwise, value is set to the parsed value and the member ec is
  value-initialized.

  Effects: The pattern is the expected form of the subject sequence in
  the "C" locale for the given non-zero base, as described for strtol,
  except that no "0x" or "0X" prefix shall appear if the value of base
  is 16, and except that a minus sign is the only sign that may appear,
  and only if value has a signed type.

== from_chars (floating-point) ==

  from_chars_result from_chars(const char* first, const char* last,
                               float& value,
                               chars_format fmt = chars_format::general);
  from_chars_result from_chars(const char* first, const char* last,
                               double& value,
                               chars_format fmt = chars_format::general);

  Effects: The pattern is the expected form of the subject sequence in
  the "C" locale, as described for strtod, except that:
    - the only sign that may appear is a minus sign
    - if fmt has chars_format::scientific set but not chars_format::fixed,
      the otherwise optional exponent part shall appear
    - if fmt has chars_format::fixed set but not chars_format::scientific,
      the optional exponent part shall not appear
    - if fmt is chars_format::hex, the prefix "0x" or "0X" is assumed

  [Example: The string 0x123 is parsed to have the value 0 with remaining
  characters x123.]

  In any case, the resulting value is one of at most two floating-point
  values closest to the value of the string matching the pattern, after
  rounding according to round_to_nearest.
