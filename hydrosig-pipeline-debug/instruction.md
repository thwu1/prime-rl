A Python river network analysis pipeline at `/app/` processes NHDPlus-style topology data and daily gauge observations from `/app/data/`. Running `python3 /app/run_analysis.py` writes computed results to `/app/results.json`. The `hydrosig` package at `/app/hydrosig/` implements baseflow separation (Lyne-Hollick 1979 recursive digital filter), recession curve fitting (master recession curve via matching strip method), hydrological signature computation (flood moments, flow duration curve, Walsh-Lawler seasonality, Sankarasubramanian elasticity), and network flow accumulation with kinematic wave routing. An algorithm reference describing the intended methods is at `/app/specification.md`.

The pipeline executes end-to-end without crashing, but produces physically implausible and numerically incorrect results across all analysis components. Baseflow indices deviate from expected behavior, recession constants are unreliable, statistical signatures are wrong, and flow accumulation values are inconsistent with network geometry. Implementation errors span the full `hydrosig` package — no module should be assumed correct. Bugs range from incorrect numerical formulas and violated physical constraints to flawed algorithm logic and wrong hydraulic parameters.
