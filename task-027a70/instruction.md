The `/app/` directory contains a partially working analog elliptic (Cauer) filter design system:

- `elliptic_filter.py` — Python module for computing analog elliptic filter prototypes (zeros, poles, gain) from scratch using only numpy. Several functions are unimplemented or produce incorrect results.
- `freqresp.c` + `Makefile` — C-based frequency response analyzer for validating filter prototypes against their specifications.
- `gen_zpk.py` — Exports filter ZPK data in the format consumed by the C analyzer.
- `filter_specs.json` — Six target filter specifications (orders 3–9).

Fix all issues in the system, build the frequency response analyzer, and produce a validation report.

**Acceptance criteria:**

1. `elliptic_filter.py` public API produces numerically correct results:
   - `complete_elliptic_K(k)` matches `scipy.special.ellipk` to 1e-10 relative error
   - `cd(x, k)` satisfies cd(0,k)=1, cd(K,k)=0, cd(2K,k)=-1, even symmetry, and period-4K
   - `cd_inv(cd(x, k), k)` round-trips to 1e-8 for real arguments in [0, K]
   - `elliptic_rational(x, N, k)` satisfies R_N(1,k)=1, R_N(0,k)=0 for odd N, equiripple passband bound, and the modular symmetry identity
   - `elliptic_filter_poles_zeros(N, Rp, Rs)` matches `scipy.signal.ellip(N, Rp, Rs, 1.0, analog=True, output='zpk')` to 1e-7 relative error for all specifications in `/app/filter_specs.json`
   - All filter zeros must be purely imaginary; all poles in the left half-plane
   - Correct passband ripple and stopband attenuation in the frequency response
   - Must not import scipy, mpmath, or any other special-function library

2. The C frequency response analyzer is built at `/app/freqresp` and produces correct `|H(jw)|` magnitude and dB output for arbitrary ZPK filter data.

3. `/app/validation_report.json` exists, generated by running the full tool pipeline (Python module → `gen_zpk.py` → C analyzer) for each specification in `/app/filter_specs.json`:
   ```json
   {
     "filters": [
       {
         "N": <order>, "Rp": <float>, "Rs": <float>,
         "dc_gain_db": <|H(j*0.01)| in dB from C analyzer>,
         "passband_edge_db": <|H(j*1.0)| in dB from C analyzer>,
         "num_zeros": <int>, "num_poles": <int>
       }
     ]
   }
   ```
