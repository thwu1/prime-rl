The CPPDubovSystem pairing engine source code is at `/app/engine/`. It implements the FIDE Dubov Swiss pairing algorithm. A tournament specification at `/app/tournament_spec.json` defines 12 players with ratings and a deterministic outcome function.

Build the engine from source, then simulate a 5-round Swiss tournament: for each round, generate pairings using the engine, determine game results via the deterministic outcome function in the specification, update the tournament state in TRF16 format, and repeat. After 5 rounds, generate the round 6 pairings from the final state.

No TRF16 specification document is provided — study the engine's source code (particularly `DubovSystem/trf_util/trf.cpp` for parsing and `DubovSystem/trf_util/rtg.cpp` for TRF generation) and the example `.trf` files in `DubovSystem/tests/` to understand the exact format and byte positions the engine expects.

Produce the following files:

- `/app/tournament.trf` — Valid TRF16 file encoding the complete tournament state after 5 rounds. Must pass the engine's Free Pairings Checker (`--fpc`) for all rounds 1 through 5 with zero errors and zero unmatched pairings.

- `/app/round6_pairings.csv` — Round 6 pairings as generated by the engine from the completed TRF file. CSV with `White,Black` columns containing player starting ranks.

- `/app/analysis.json` — JSON object with these fields:
  - `aro`: object mapping player ID strings to integer ARO (Average Rating of Opponents) after round 5. Only count over-the-board games (result codes `1`, `0`, `=`), not forfeits or byes. Round to nearest integer; 0.5 rounds up.
  - `color_diff`: object mapping player ID strings to integer color difference (games as white minus games as black) after round 5. Only count games where an actual color (`w` or `b`) was assigned.
  - `scoregroups`: object mapping score strings (e.g. `"3.5"`) to sorted arrays of player IDs sharing that score after round 5.
  - `round6_pairings`: array of `[white_id, black_id]` pairs for round 6.
