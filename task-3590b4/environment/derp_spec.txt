DERP Protocol Wire Format Reference
====================================

DERP (Designated Encrypted Relay for Packets) is a packet relay protocol
used by Tailscale to proxy encrypted WireGuard packets when direct peer-to-peer
connections cannot be established. Peers are addressed using curve25519
public keys (32 bytes) instead of IP addresses.

Protocol Version: 2

Constants
---------
  Magic:          "DERP🔑"  (8 bytes: 0x44 0x45 0x52 0x50 0xf0 0x9f 0x94 0x91)
  NonceLen:       24 bytes
  KeyLen:         32 bytes
  FrameHeaderLen: 5 bytes  (1 byte type + 4 byte big-endian uint32 length)
  MaxPacketSize:  65536 bytes (64 KiB)

Frame Header
------------
Every frame begins with a 5-byte header:

  Offset  Size  Description
  0       1     FrameType byte
  1       4     Big-endian uint32: payload length (NOT including the 5-byte header)

The payload immediately follows the header.

Frame Types
-----------

0x01 - ServerKey
  Server -> Client, sent upon initial connection.
  Payload: [8 bytes magic] [32 bytes server public key] [0+ bytes reserved]
  Minimum payload length: 40 bytes.

0x02 - ClientInfo
  Client -> Server, handshake response.
  Payload: [32 bytes client public key] [24 bytes nonce] [N bytes NaCl box encrypted JSON]

0x03 - ServerInfo
  Server -> Client, after ClientInfo.
  Payload: [24 bytes nonce] [N bytes NaCl box encrypted JSON]

0x04 - SendPacket
  Client -> Server, send a packet to a destination peer.
  Payload: [32 bytes destination public key] [N bytes packet data]

0x05 - RecvPacket  (Protocol Version 2)
  Server -> Client, delivers a received packet.
  Payload: [32 bytes source public key] [N bytes packet data]
  Note: In v2, the source key is always present as the first 32 bytes.

0x06 - KeepAlive
  Server -> Client, no-op to keep connection alive.
  Payload: empty (0 bytes).

0x07 - NotePreferred
  Client -> Server, declares home node preference.
  Payload: [1 byte] 0x01 = preferred (home), 0x00 = not preferred.

0x08 - PeerGone
  Server -> Client, a peer is no longer reachable.
  Payload: [32 bytes peer public key] [1 byte reason code]
  Reason codes:
    0x00  Disconnected   (peer disconnected from this server)
    0x01  NotHere        (server has no record of this peer)

0x09 - PeerPresent
  Server notification about a connected peer (used in mesh mode).
  Payload is VARIABLE LENGTH:
    [32 bytes peer public key]                         -- always present
    [16 bytes IP address] [2 bytes BE uint16 port]     -- present if >= 18 bytes remain after key
    [1 byte PeerPresentFlags]                          -- present if >= 1 byte remains after IP+port

  IP address encoding: 16 bytes. IPv4 addresses use IPv4-mapped IPv6 format:
    bytes 0-9:   0x00 (ten zero bytes)
    bytes 10-11: 0xFF 0xFF
    bytes 12-15: 4 IPv4 address bytes

  PeerPresentFlags bits:
    bit 0 (0x01): IsRegular
    bit 1 (0x02): IsMeshPeer
    bit 2 (0x04): IsProber
    bit 3 (0x08): NotIdeal

0x0a - ForwardPacket
  Mesh node forwarding.
  Payload: [32 bytes source public key] [32 bytes destination public key] [N bytes packet data]

0x10 - WatchConns
  Mesh subscription request, no payload. Subscribes to PeerPresent/PeerGone streams.

0x11 - ClosePeer
  Privileged: force-close a peer connection (mesh key required).
  Payload: [32 bytes peer public key]

0x12 - Ping
  Ping request.
  Payload: [8 bytes ping data]

0x13 - Pong
  Pong reply, echoes back ping data.
  Payload: [8 bytes echoed ping data]

0x14 - Health
  Server -> Client, health status notification.
  Payload: UTF-8 text string (variable length).
  An empty payload clears the error state.

0x15 - Restarting
  Server -> Client, server restart announcement.
  Payload: [4 bytes BE uint32 reconnect_ms] [4 bytes BE uint32 try_for_ms]
  reconnect_ms: advisory wait before reconnecting
  try_for_ms: how long to keep attempting reconnection

Protocol Flow
-------------
Login handshake:
  1. Client connects (TCP/TLS)
  2. Server sends ServerKey
  3. Client sends ClientInfo
  4. Server sends ServerInfo

Steady state:
  - Server periodically sends KeepAlive or Ping
  - Client replies to Ping with Pong (echoing the 8-byte payload)
  - Client sends SendPacket to relay data to a destination peer
  - Server delivers RecvPacket to the destination client
  - Server sends PeerGone when a peer disconnects
  - Server sends Health if connection state is degraded
  - Server sends Restarting before graceful shutdown
